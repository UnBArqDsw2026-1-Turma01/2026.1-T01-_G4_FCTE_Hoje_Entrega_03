# 3.2. Módulo Padrões de Projeto GoFs Estruturais

## 1. Introdução

Conforme apresentado no livro **Design Patterns: Elements of Reusable Object-Oriented Software**, os **Padrões de Projeto Estruturais**, definidos pela **Gang of Four (GoF)**, têm como objetivo organizar classes e objetos para formar estruturas maiores e mais flexíveis, facilitando a criação de sistemas extensíveis e de fácil manutenção.

Esses padrões **tratam da forma como classes e objetos são compostos**, seja por meio de herança (composição estrutural de classes) ou por associação entre objetos (composição dinâmica durante a execução). Enquanto os padrões estruturais de classe combinam interfaces e implementações por herança, os **padrões estruturais de objeto permitem criar novas funcionalidades combinando objetos em tempo de execução, oferecendo maior flexibilidade**.

Ao ocultar a complexidade das interações internas e promover abstrações unificadas, os padrões estruturais possibilitam integrar componentes independentes, adaptar interfaces incompatíveis, criar hierarquias complexas de composição e compartilhar objetos de forma eficiente ([GAMMA et al., 1995](https://www.javier8a.com/itc/bd1/articulo.pdf)).

## 2. Metodologia

Embora os Padrões de Projeto Criacionais incluam **Adapter, Bridge, Composite, Decorator, Facade, Flyweight e Proxy**, conforme apresentado pela professora Milene Serrano **(SERRANO, 2026)**, considerando a etapa de [Modelagem de Software](https://unbarqdsw2026-1-turma01.github.io/2026.1-T01-_G4_FCTE_Hoje_Entrega_02/#/), bem como a redução de escopo e a adequação ao projeto FCTE Hoje, foram aplicados os seguintes padrões na fase atual:


- [Adapter](./3.2.1.Adapter.mdd): permite que objetos com interfaces incompatíveis colaborem.
- [Composite](./3.2.2.Composite.md): permite juntar objetos em estruturas de árvore e trabalhar com essas estruturas como se fossem objetos individuais.
- [Decorator](./3.2.3.Decorator.md): permite adicionar novos comportamentos a objetos, colocando esses objetos dentro de “envoltórios” especiais que contêm esses comportamentos.
- [Proxy](./3.2.4.Proxy.md): fornece um substituto ou representante para outro objeto, controlando o acesso a ele.
