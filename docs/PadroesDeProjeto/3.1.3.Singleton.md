# 3.1.3 Singleton

## 1. Visão Geral

O Singleton consiste em um padrão de design estruturado para restringir a inicialização de uma classe a um único objeto, assegurando, simultaneamente, um canal centralizado e universal para a sua recuperação.

## 3. Aplicabilidade

Utilize o padrão Singleton quando uma classe em seu programa deve ter apenas uma instância disponível para todos seus clientes; por exemplo, um objeto de base de dados único compartilhado por diferentes partes do programa.

## 4. Prós

- Você pode ter certeza que uma classe só terá uma única instância.
- O objeto singleton é inicializado somente quando for pedido pela primeira vez.
- Você ganha um ponto de acesso global para aquela instância.

## 5. Contras

- Viola o princípio de responsabilidade única. O padrão resolve dois problemas de uma só vez.
- O padrão Singleton pode mascarar um design ruim, por exemplo, quando os componentes do programa sabem muito sobre cada um.
- O padrão requer tratamento especial em um ambiente multithreaded para que múltiplas threads não possam criar um objeto singleton várias vezes.
- Pode ser difícil realizar testes unitários do código cliente do Singleton porque muitos frameworks de teste dependem de herança quando produzem objetos simulados. Já que o construtor da classe singleton é privado e sobrescrever métodos estáticos é impossível na maioria das linguagem, você terá que pensar em uma maneira criativa de simular o singleton. Ou apenas não escreva os testes. Ou não use o padrão Singleton.

## 6. Implementação

Para o FCTE Hoje, verificamos a necessidade de lidar com o armazenamento de dados do usuário e consumo de internet como uma oportunidade de otimização. Daí, o Singleton surgiu como um encaixe perfeito para resolver esses nossos dois requisitos de uma vez:

- RNF03 (Modo Offline): O app precisa mostrar informações salvas (como o cardápio do RU) mesmo sem internet.
- RNF04 (Sincronização): Os dados devem ser atualizados obrigatoriamente a cada 24 horas.

O problema: Se cada tela do app (Notícias, Eventos, RU) criasse o seu próprio gerenciador de rede e cache, o aplicativo viraria uma bagunça. Várias telas tentariam baixar e salvar os mesmos dados ao mesmo tempo, travando o celular, gastando a franquia de dados do aluno à toa e bagunçando a contagem das 24 horas.

A solução: Criamos a classe GerenciadorDeCache usando o Singleton. Ele garante que exista apenas uma única instância dessa classe rodando na memória do aplicativo inteiro. Ele funciona como o "maestro" do armazenamento: todas as telas pedem os dados para ele, e só ele decide se é hora de ler do arquivo offline ou se é hora de baixar da internet.

### 6.1. Código de Implementação 

``` python
import datetime

class GerenciadorDeCache:

    _instancia = None

    def __new__(cls):
        
        if cls._instancia is None:
            cls._instancia = super(GerenciadorDeCache, cls).__new__(cls)
            # Garante que o estado inicial rode apenas UMA vez
            cls._instancia._inicializar_estado()
            print("[SISTEMA] Gerenciador de Cache criado na memória pela 1ª vez.")
        
        return cls._instancia

    def _inicializar_estado(self) -> None:
        
        self._cache_local = {}
        self._ultima_sincronizacao = None
        self._conectado_internet = False

    def set_conexao_internet(self, status: bool) -> None:
        
        self._conectado_internet = status
        print(f"\n[REDE] Internet ativa? {self._conectado_internet}")
        
        if self._conectado_internet:
            self._tentar_sincronizar()

    def _tentar_sincronizar(self) -> None:
        
        agora = datetime.datetime.now()
        nunca_sincronizou = self._ultima_sincronizacao is None
        
        passou_de_24h = False
        if not nunca_sincronizou:
            diferenca = agora - self._ultima_sincronizacao
            passou_de_24h = diferenca.total_seconds() > 86400  

        precisa_sincronizar = nunca_sincronizou or passou_de_24h

        if precisa_sincronizar and self._conectado_internet:
            print("[SYNC] Baixando dados do servidor da FCTE...")
            
            self._cache_local["noticias"] = ["Notícia 1: Semana Acadêmica", "Notícia 2: Novo Edital"]
            self._cache_local["ru"] = "Almoço: Frango Assado | Jantar: Strogonoff"
            
            self._ultima_sincronizacao = agora
            print("[SYNC] Sucesso! Relógio de 24 horas reiniciado.")
            
        elif precisa_sincronizar and not self._conectado_internet:
            print("[AVISO] App precisa sincronizar, mas está offline. Mantendo cache antigo.")

    def obter_dado(self, chave: str):
        
        self._tentar_sincronizar()
        
        if chave in self._cache_local:
            print(f"[APP] Lendo '{chave}' do cache: {self._cache_local[chave]}")
            return self._cache_local[chave]
        else:
            print(f"[ERRO] Dado '{chave}' não existe no cache.")
            return None

if __name__ == "__main__":
    print("--- 1. App abriu na Tela Principal (Sem internet) ---")
    cache_home = GerenciadorDeCache()
    cache_home.set_conexao_internet(False)
    cache_home.obter_dado("noticias") 

    print("\n--- 2. Usuário conectou no Wi-Fi ---")
    cache_home.set_conexao_internet(True)

    print("\n--- 3. Usuário navegou para a Tela do RU ---")
    cache_ru = GerenciadorDeCache() 
    cache_ru.obter_dado("ru") 

    print("\n--- 4. Comprovando o Singleton na prática ---")
    if cache_home is cache_ru:
        print("SUCESSO! 'cache_home' e 'cache_ru' são o exato mesmo objeto na memória.")
        
```

### 6.2. Senso Crítico

Em vez de desenhar um diagrama travado nos padrões de linguagens como Java ou C++, nós montamos um Diagrama de Implementação que reflete como o Python realmente funciona:

- Protegendo os dados: O Python não tem a palavra private para bloquear o acesso de fora. Por isso, usamos a convenção da própria linguagem: atributos e métodos internos (como a _ultima_sincronizacao e o _tentar_sincronizar()) começam com um underline (_). No diagrama, sinalizamos isso com o símbolo de menos (-).
- Instância Única Nativa: Em vez de criar um método chato como getInstance(), nós usamos o método mágico do Python chamado __new__. Quando qualquer tela do app tenta "criar" o cache, esse método intercepta o pedido e simplesmente devolve a instância que já está pronta na memória. Fica mais limpo e segue as boas práticas da linguagem (PEP 8).
