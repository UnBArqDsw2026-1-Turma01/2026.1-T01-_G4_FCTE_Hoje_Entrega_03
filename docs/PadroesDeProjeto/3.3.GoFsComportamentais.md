# 3.3. Módulo Padrões de Projeto GoFs Comportamentais

## 1. Introdução

Conforme apresentado no livro **Design Patterns: Elements of Reusable Object-Oriented Software**, os **Padrões de Projeto Comportamentais**, definidos pela **Gang of Four (GoF)**, têm como objetivo organizar algoritmos e distribuir responsabilidades entre objetos, descrevendo não apenas comportamentos individuais, mas também os padrões de comunicação e cooperação entre eles.

Esses padrões **ajudam a lidar com fluxos de controle complexos**, tornando o sistema mais compreensível ao deslocar o foco da sequência explícita de execução para a forma como os objetos se relacionam e interagem. Dessa forma, **promovem sistemas mais flexíveis e de menor acoplamento, facilitando a evolução do comportamento sem impactos estruturais severos**.

Os padrões comportamentais podem atuar tanto em nível de classes, usando herança para definir partes variáveis de algoritmos, quanto em nível de objetos, empregando composição para orquestrar colaboração entre múltiplas instâncias ([GAMMA et al., 1995](https://www.javier8a.com/itc/bd1/articulo.pdf)).

## 2. Metodologia

Embora os Padrões de Projeto Criacionais incluam **Chain of Responsibility, Command, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method e Visitor** ([GAMMA et al., 1995](https://www.javier8a.com/itc/bd1/articulo.pdf)), considerando a etapa de [Modelagem de Software](https://unbarqdsw2026-1-turma01.github.io/2026.1-T01-_G4_FCTE_Hoje_Entrega_02/#/), bem como a redução de escopo, a adequação ao projeto FCTE Hoje e os conteúdos apresentados pela professora Milene Serrano **(SERRANO, 2026)**, foram aplicados os seguintes padrões na fase atual:


- [Mediator](/PadroesDeProjeto/3.3.1.Mediator.md): permite reduzir dependências caóticas entre objetos, restringindo a comunicação direta entre eles e obrigando que colaborem apenas por meio de um objeto mediador.
- [Observer](/PadroesDeProjeto/3.3.2.Observer.md): permite definir um mecanismo de assinatura para notificar vários objetos sobre eventos que acontecem no objeto que eles estão observando.
- [Strategy](/PadroesDeProjeto/3.3.3.Strategy.md): permite definir uma família de algoritmos, colocar cada um em uma classe separada e tornar seus objetos intercambiáveis.
